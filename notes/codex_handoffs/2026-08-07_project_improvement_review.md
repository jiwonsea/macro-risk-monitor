## 1. [구조] 블로그 채점 체계가 저장소의 기존 엔진을 손으로 재구현하고 있다

**제안 1-B.** 판정 기계화. `criterion_hit`을 `engine/trigger.py`가 평가할 수 있는 비교식(`EMRATIO <= 59.0`)으로 쓰고, 산문 기준은 `judgment: manual` 플래그를 강제한다.

**Codex에게 묻는다.**

## 2. [치명] 개정(vintage) 규칙이 아예 없다 — 이번에 판정을 실제로 위협했다

**근거 2.** 7월 고용에서 5월 129k→63k, 6월 57k→20k. 원글 6장이 인용한 시퀀스(`214k → 148k → 129k → 57k`)가 통째로 무효가 됐다.

**현재 상태.** `Reading.as_of`는 **관측월**이지 발표일도 빈티지도 아니다. `scorecard.csv`엔 빈티지 개념 자체가 없다. 즉 "어느 시점의 숫자로 채점하는가"가 **어디에도 정의돼 있지 않다.**

**제안 2-A (규칙).** 판정은 **최초 발표치(first print)** 기준. 개정치는 `note`에 병기하되 판정을 바꾸지 않는다. 근거: 예측 시점의 예측자가 볼 수 있었던 정보로 채점해야 사후 유리한 빈티지를 고르는 일이 원천 차단된다.

**제안 2-B (스키마).** `scorecard.csv`에 `actual_first_print` / `actual_current` 두 열 분리.

**제안 2-C (재현성).** ALFRED(FRED 빈티지 DB)로 first print를 프로그램적으로 취득.

**Codex에게 묻는다.**

## 4. [설계] 기준이 수준만 묻고 방향을 묻지 않는다

**근거.** 8/7에 P5~P9가 전부 적중했다(EMRATIO 58.9 / CIVPART 61.4 / UNRATE 4.1 / NILFWJN YoY −266k / AHE 3.2%). 같은 날 비농업 고용이 **−23k**로 돌아섰고 두 달치가 **−103k** 하향 개정됐다. 원글 6장이 tail과 base를 가른 근거 문장은 "**해고가 늘어난 게 아니라 노동공급이 줄어드는 중**"이다. 그 근거가 흔들렸는데 **채점표는 한 칸도 움직이지 않았다.** P5~P9가 전부 "수준이 이 선 아래인가"만 묻기 때문이다.

**제안 4-A.** 다음 글 예측 등록 시 **사전 확률(0~1) 필수 + Brier score**. 그래야 "동결이 컨센서스인 상황에서 동결을 예측한 것"이 낮은 점수를 받고, 쉬운 예측만 고른 편향이 점수에 드러난다.

**제안 4-B.** 각 예측에 **반증 조건(무엇이 관측되면 이 예측을 틀린 것으로 볼 것인가)** 을 등록 시점에 필수 기입. 이번 사건은 "예측은 맞았는데 논지는 틀렸다"인데, 논지 수준의 반증 조건이 P13 하나뿐이었고 그마저 논리식이 뒤집혀 있었다.

**Codex에게 묻는다.**
- (a) v1 기준 아래 9적중인데, v2 기준의 P13("인플레 지속 지표 1개와 노동수요 악화 지표 1개가 같은 평가창에서 동시 충족")을 지금 데이터에 적용하면 **Core PCE 3.29% + 비농업 −23k**로 조건이 충족된다. 즉 **기준을 언제 바꾸느냐가 결론(tail/base)을 뒤집는다.** 이 관찰이 성립하는가, 아니면 내가 v2 문구를 확대해석했는가?
- (b) Brier score 도입이 개인 블로그 규모에서 실효가 있는가? 15개 표본으로 의미 있는 신뢰도 곡선이 나오는가?
- (c) 4-B의 "반증 조건"이 결국 기준을 하나 더 쓰는 것에 불과하지 않은가?
